# 모아 ✦

가입 없이 친구와 지도·할 일·사진을 모으는 가벼운 협업 PWA입니다.
Svelte 5 + TypeScript + Vite / Cloudflare Workers + D1 + 비공개 R2.

처음이라면 **[SETUP.md](SETUP.md)** 에서 계정 생성·지도 키 제한·DB·사진 저장소·배포 순서를 따라가세요.

빠른 로컬 시작: `npm ci` → `npm start` → `http://localhost:5173`. 키 없이 목록·공유·사진을 먼저 테스트할 수 있습니다.
설정 확인: `npm run doctor`. 배포 전 확인: `npm run doctor:deploy`.

## 준비할 것

사용자는 가입하지 않습니다. 서비스를 배포하는 운영자는 다음을 준비합니다.

| 준비물                                          | 용도                                    | 필수 여부                   |
| ----------------------------------------------- | --------------------------------------- | --------------------------- |
| Node.js 22.12 이상, npm                         | 로컬 실행·빌드                          | 필수                        |
| Cloudflare 운영자 계정                          | Workers·D1·R2 배포                      | 온라인 공유 시 필수         |
| D1 데이터베이스                                 | 프로젝트·장소·변경 버전·사진 메타데이터 | 필수                        |
| 비공개 R2 버킷                                  | 프로젝트 사진                           | 사진 공유 시 필수           |
| Google Cloud 프로젝트·결제 설정·브라우저 API 키 | Maps JavaScript API, Places API (New)   | 지도·검색 시 필수           |
| GitHub 저장소                                   | MIT 소스 공개                           | 선택                        |
| 도메인                                          | 운영 주소                               | 선택, workers.dev 사용 가능 |

R2는 계정에서 활성화해야 하며 결제 수단이 필요할 수 있습니다. 요금제·무료 범위는 배포 시 확인하세요. Google 지도·검색은 과금될 수 있습니다. 예산 알림이 사용량을 자동 차단하는 것은 아니므로 API별 쿼터도 설정하세요.

## 로컬 실행

```bash
npm ci
cp .env.example .env.local
# .env.local에 Google Maps 키 입력 (키 없이도 목록·공유·사진 테스트 가능)
npm run build
npm run db:local
npm run server
```

다른 터미널에서:

```bash
npm run dev
```

브라우저에서 `http://localhost:5173`을 엽니다. Vite가 `/api`를 로컬 Workers 서버(8787)로 전달합니다. 로컬 D1·R2는 Wrangler가 에뮬레이션하므로 Cloudflare 로그인 없이 개발 가능합니다. 소스 수정 후 PWA 자체를 검증하려면 다시 빌드하고 Workers 주소 `http://localhost:8787`에서 확인하세요.

## 실제 배포

```bash
npx wrangler login
npx wrangler d1 create compass
npx wrangler r2 bucket create moa-private-photos
```

D1 생성 결과의 database_id를 `wrangler.toml`에 넣습니다. R2 버킷은 공개 접근을 켜지 않습니다. 버킷명이 이미 사용 중이면 바꾸고 설정도 일치시킵니다.

```bash
npm run db:remote
npm run check
npm test
npm run deploy
```

빌드 전에 `.env.local`의 키를 설정하세요. Google Cloud에서 Maps JavaScript API와 Places API (New)를 활성화하고 API 키에 **허용 웹사이트 HTTP referrer 제한과 두 API 제한**을 걸어주세요. 개발 주소와 배포 주소만 허용합니다. 브라우저 지도 키는 공개되므로 서버 비밀 키처럼 취급하는 대신 제한을 반드시 적용해야 합니다.

## 사용 흐름

1. 별명과 프로젝트 이름으로 생성 → 지도 화면으로 시작.
2. 초대 코드와 별도 관리 키를 받습니다. 관리 키 파일을 따로 저장하세요.
3. 친구는 같은 사이트에서 코드와 별명으로 입장합니다. 계정·메일 불필요.
4. 지도 검색 결과를 선택하거나 지도 클릭으로 좌표 지정, 직접 입력도 가능합니다.
5. 항목 상세 → 사진 담기. 브라우저에서 최대 1600px WebP로 변환합니다(최대 2MB).
6. 친구는 상세의 사진 보기를 눌러 내려받습니다. 목록 진입만으로 사진을 내려받지 않습니다.
7. JSON 백업 / CSV·JSON 가져오기로 텍스트 항목을 이동합니다.

사진 원본은 저장하지 않습니다. 캔버스로 새 이미지를 생성해 일반 EXIF 정보를 전달하지 않습니다. 사진은 프로젝트 참여 세션으로만 읽으며 공개 URL을 만들지 않습니다. 참여자는 사진 저장·삭제와 항목 편집 권한이 동일합니다. 개인별 삭제 권한은 구현하지 않았습니다. 프로젝트당 사진 200장, 업로드 전 원본 20MB 제한입니다. 사진 파일은 JSON 백업에 포함되지 않습니다.

## 가져오기 범위

CSV 헤더 예시:

```csv
title,category,address,note,url,date
작은 카페,food,서울,라떼 먹어보기,https://map.naver.com/,2026-12-01
```

category: place / food / stay / task. 한 번에 200개, 파일 2MB까지.
현재 공유 링크는 원본 참조로 저장합니다. **구글·네이버 개인 저장 목록 자동 수집, 짧은 링크 자동 해석, 자동 장소 매칭은 구현하지 않았습니다.** 공식 권한·내보내기 형식 검증 후 추가해야 합니다. 가져온 장소의 좌표는 검색 또는 직접 입력으로 지정합니다. 외부 리뷰·사진·영업시간은 복제하지 않습니다.

## 데이터 사용과 동기화

- 초기 지도 화면이므로 프로젝트 입장 시 Google 지도를 요청합니다. 저데이터 목록 모드에서는 지도를 숨깁니다. 이미 내려받은 지도 SDK를 되돌려 회수하지는 못합니다.
- 사진은 자동 다운로드하지 않으며, 이미지 업로드 전 압축합니다. 외부 폰트·아이콘 패키지 없음.
- 수정 항목만 전송하고 이후 변경분만 수신합니다. 보이는 화면에서 60초마다 확인하고 화면 복귀·재연결 시 확인합니다.
- IndexedDB에 목록·전송 대기를 보관합니다. 오프라인에서 텍스트 편집 가능. 지도·검색·사진 조회/업로드에는 연결 필요.
- 버전 충돌 시 자동 덮어쓰기를 중단합니다. JSON으로 내 편집을 백업하고 대기 변경 취소 후 다시 수정합니다.
- PWA는 방문한 앱 자산을 캐시합니다. 오프라인 지도는 제공하지 않습니다.

## 권한과 운영상 한계

코드는 서버가 만든 96비트 무작위 값이며 SHA-256 해시로 저장합니다. 세션·관리 키는 192비트 무작위 값이고 서버에는 해시만 저장합니다. 참여 입력은 IP당 분당 12회 제한합니다. 세션은 30일 후 만료되어 코드로 다시 입장해야 합니다. 코드 재발급은 관리자의 현재 세션만 남기고 다른 세션을 해제합니다. 코드만으로 들어온 친구도 관리 키를 알고 있다면 관리 작업을 할 수 있습니다.

별명은 본인 인증 수단이 아닙니다. 코드·관리 키를 잃으면 계정으로 복구할 수 없습니다. 브라우저에는 접근용 세션·초대 코드·생성자 관리 키가 저장되므로 공유 기기에서는 사이트 데이터를 지우세요. 관리 키 분실 시 운영자가 DB에서 별도 조치해야 합니다.

비공개 접근 제어를 사용하지만 종단간 암호화는 아닙니다. 운영자는 저장소에 접근할 수 있습니다. 프로젝트 삭제 시 사진과 데이터가 삭제되며 복구 기능은 없습니다. 삭제한 개별 장소의 사진은 프로젝트 삭제 전까지 저장소에 남을 수 있습니다. 저비용 베타용 구조로, 공개 운영 전 데이터 보존 정책·백업·사용량 제한을 정하세요. 사진 200장 제한은 동시 업로드 시 소폭 초과할 수 있습니다. 대규모 서비스는 트랜잭션 기반 할당량과 업로드 속도 제한이 추가로 필요합니다.

## 파일 구조

- `src/App.svelte`: 지도·목록·초대·사진·오프라인 편집 UI
- `src/style.css`: 반응형 화면
- `server/index.ts`: 코드 인증, 프로젝트 API, 충돌 확인, 비공개 사진 API
- `server/validation.ts`: 외부 링크·좌표·입력 검증
- `migrations/`: D1 테이블
- `public/sw.js`: 앱 자산 캐시(서버 데이터·사진 제외)
- `tests/`: 입력 검증 테스트

## 이번 구현의 검증 결과

- `npm run check`: TypeScript·Svelte 오류 0, 경고 0.
- `npm test`: 링크·좌표·항목 검증 테스트 3개 통과.
- `node tests/integration.mjs`: 로컬 Workers + D1 + R2에서 코드 참여, 변경 공유, 버전 충돌, 프로젝트 간 사진 접근 차단, 코드 재발급과 삭제 통과. 로컬 서버를 켠 상태에서 실행합니다.
- Chromium 브라우저에서 프로젝트 생성, 항목 추가, 사진 압축·업로드·조회, 상세 모달, 프로젝트 삭제 확인. 390px 모바일 화면 가로 넘침 없음.
- 지도 키가 없어 실제 Google 지도 타일·장소 검색 결과는 미검증. `docs/` 이미지는 API 키 미설정 상태입니다.
- 실서비스 배포와 외부 플랫폼 저장 목록 자동 가져오기는 진행하지 않았습니다.
