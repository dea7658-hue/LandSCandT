# 모아 시작하기 — 준비부터 배포까지

이 문서는 서비스를 만드는 운영자 한 명을 위한 안내입니다. 친구들은 가입 없이 프로젝트 코드로만 참여합니다. Google·Cloudflare 계정은 운영자만 준비합니다.

## 1. 먼저 로컬에서 실행하기 (계정·결제 없이 가능)

### 설치

1. https://nodejs.org/ 에서 Node.js 24 LTS를 설치합니다. Node.js 22.12 이상도 사용할 수 있습니다.
2. 소스 압축을 풀고 `package.json`이 들어 있는 `moa` 폴더를 VS Code 같은 편집기로 엽니다. 현재 개발 환경의 폴더명은 `compass`입니다.
3. 그 폴더에서 터미널을 열고 아래 명령을 실행합니다.

```bash
node --version
npm --version
npm ci
npm start
```

처음 실행 시 의존성을 설치한 뒤 설정 점검 → 필요한 경우 빌드 → 로컬 DB 생성 → 공유 서버와 화면 서버 시작이 진행됩니다. 터미널을 닫으면 개발 서버도 종료됩니다.

브라우저에서 **http://localhost:5173** 을 엽니다. 처음에는 `새 여행 만들기`로 프로젝트를 생성합니다. 다른 브라우저나 시크릿 창에서 같은 주소를 열고 `코드로 참여`를 선택하면 친구 참여를 시험할 수 있습니다.

**API 키 없이도 가능한 것:** 프로젝트 생성·코드 참여·장소 직접 입력·할 일·메모·사진 업로드·참여자 간 사진 조회. 지도는 설정 안내 화면으로 표시됩니다. 사진 저장소와 DB는 컴퓨터에서 에뮬레이션되며 Cloudflare 원격 저장소에 업로드되지 않습니다.

`localhost`는 그 기기 자신을 뜻합니다. 친구 휴대폰에서 내 PC의 localhost 주소를 열어 사용할 수는 없습니다. 휴대폰 공동 사용과 PWA·사진 API 호환성 검증에는 아래 HTTPS 배포 주소를 사용하세요.

## 2. Google 지도 키 준비하기

### Google Cloud 프로젝트와 결제 연결

1. https://console.cloud.google.com/ 에 접속해 운영자 Google 계정으로 로그인합니다.
2. 프로젝트 선택 메뉴에서 새 프로젝트를 만듭니다. 예: `moa-travel`.
3. 결제 메뉴에서 결제 계정을 연결합니다. 지도 플랫폼은 사용량에 따라 비용이 발생합니다.
4. API 라이브러리에서 다음을 찾아 활성화합니다.
   - **Maps JavaScript API**: 세계 지도 표시.
   - **Places API (New)**: 장소명 검색 및 위치 선택.
5. API 및 서비스의 사용자 인증 정보 메뉴에서 API 키를 생성합니다. 콘솔 메뉴 이름은 변경될 수 있지만 위 API 이름은 동일한 항목을 찾으면 됩니다.

### 키 제한 설정

애플리케이션 제한을 **웹사이트(HTTP referrer)** 로 선택하고 다음 주소를 등록합니다.

```text
http://localhost:5173/*
http://127.0.0.1:5173/*
http://localhost:8787/*
http://127.0.0.1:8787/*
```

나중에 배포한 실제 주소도 추가합니다. 예:

```text
https://moa-example.your-subdomain.workers.dev/*
```

API 제한은 **Maps JavaScript API와 Places API (New)** 로 한정합니다. 별도 개발용 키와 운영용 키로 분리하면 더 관리하기 쉽습니다.

### 앱에 키 넣기

프로젝트 폴더에 `.env.local` 파일을 만들고 아래 한 줄을 넣습니다. `.env.example`을 복사해 만들어도 됩니다.

```dotenv
VITE_GOOGLE_MAPS_API_KEY=발급받은_실제_브라우저_API_키
```

파일 이름은 `.env.local`이며 끝에 `.txt`가 붙지 않게 합니다. Windows에서는 파일 확장명 표시를 켜서 확인하세요. 파일은 Git에 올리지 않습니다. 키 값은 채팅으로 보낼 필요가 없습니다.

개발 서버를 종료하고 `npm start`로 다시 시작합니다. 이미 빌드한 배포 파일을 바꾸려면 `npm run build`도 다시 실행해야 합니다. Vite는 키를 빌드 시점에 넣으므로 Workers 서버의 런타임 환경 변수만 바꿔서는 기존 화면에 반영되지 않습니다.

### 비용 설정

Google Cloud에서 월 예산 알림과 API별 요청 쿼터를 설정합니다. 예산 알림만으로 비용이 자동 차단되지는 않습니다. 검색은 검색 버튼을 눌렀을 때만 요청하지만, 지도 화면을 처음 열 때도 지도 로딩 비용과 데이터 사용이 발생할 수 있습니다. 무료 범위와 단가는 운영 시작 시 공식 가격표에서 확인하세요.

## 3. Cloudflare 계정과 저장소 준비하기

### 계정 연결

1. https://dash.cloudflare.com/ 에서 운영자 계정을 만듭니다.
2. Workers 서비스 이용을 준비하고 R2를 활성화합니다. R2 활성화 시 결제 수단 등록을 요구할 수 있습니다.
3. 프로젝트 폴더의 터미널에서 실행합니다.

```bash
npx wrangler login
```

브라우저에서 로그인과 권한 요청을 확인합니다. 이 절차는 운영자만 합니다.

### D1 데이터베이스 생성

```bash
npx wrangler d1 create compass
```

결과에서 `database_id`를 찾아 `wrangler.toml`의 아래 부분에 넣습니다. 기존 바인딩 이름 `DB`는 유지합니다.

```toml
[[d1_databases]]
binding = "DB"
database_name = "compass"
database_id = "여기에_생성된_실제_UUID"
migrations_dir = "migrations"
```

이미 같은 이름의 DB를 만든 경우 새로 만들지 않고 대시보드 또는 `npx wrangler d1 list`에서 ID를 확인합니다. 계정·DB 이름이 서로 맞아야 합니다.

### 사진용 비공개 R2 버킷 생성

```bash
npx wrangler r2 bucket create moa-private-photos
```

`wrangler.toml`에 다음 항목이 있는지 확인합니다.

```toml
[[r2_buckets]]
binding = "PHOTOS"
bucket_name = "moa-private-photos"
```

다른 버킷명을 사용했다면 설정도 함께 바꿉니다. 버킷의 `r2.dev` 공개 URL과 공개 도메인을 활성화하지 않습니다. 앱은 Workers 내부 바인딩으로 저장소에 접근하므로 R2 액세스 키를 별도로 만들거나 사용자에게 전달할 필요가 없습니다. 사진은 인증된 앱 API를 통해 읽습니다.

## 4. 첫 배포하기

로컬 개발 서버는 `Ctrl+C`로 종료한 후 진행합니다.

```bash
npm run doctor:deploy
npm run db:remote
npm test
npm run deploy
```

- `doctor:deploy`: Node.js, 의존성, D1 ID 형식, 지도 키·사진 바인딩 존재 확인. 실제 원격 권한과 Google 결제 상태는 확인하지 않습니다.
- `db:remote`: 원격 D1에 테이블 생성. 기존 테이블을 지우는 명령이 아닙니다.
- `deploy`: 설정·타입 검사 후 빌드하고 Workers에 배포. 외부 URL이 만들어집니다.

첫 배포에서는 `wrangler.toml`의 `name = "compass-together"`가 서비스 이름입니다. 원하는 이름으로 바꿀 수 있습니다. 결과로 출력되는 실제 `https://…workers.dev` 주소를 저장합니다. 별도 도메인 구매는 필요하지 않습니다.

배포 주소를 Google API 키의 허용 웹사이트 목록에 추가합니다. 키 자체를 바꿨다면 다시 빌드·배포합니다. 제한 반영에는 시간이 걸릴 수 있습니다.

## 5. 배포 후 확인할 순서

1. 배포 주소의 `/api/health`를 엽니다. `ok: true`이면 DB 테이블과 사진 저장소 읽기 접근이 확인된 것입니다. 지도 키·사진 쓰기 권한까지 확인하는 검사는 아닙니다.
2. 새 프로젝트를 생성하고 관리 키 파일을 내려받아 안전하게 보관합니다.
3. 두 번째 브라우저나 친구 휴대폰에서 같은 사이트를 열고 코드로 참여합니다.
4. 지도에 실제 지형이 보이는지, 검색으로 장소를 선택할 수 있는지 확인합니다.
5. 한 사람이 장소를 추가한 뒤 다른 사람이 새로고침해 반영되는지 확인합니다.
6. 작은 사진을 올리고 친구가 `사진 보기`로 열 수 있는지 확인합니다.
7. 다른 프로젝트에서는 사진을 볼 수 없는지 확인합니다.
8. 관리자가 초대 코드를 바꾸고 친구가 새 코드로 다시 입장하는지 확인합니다.

실제 지도와 검색은 유효한 키·API 활성화·결제·웹사이트 제한이 모두 맞아야 작동합니다. 이 저장소에는 운영자 API 키가 들어 있지 않습니다.

## 6. 오픈소스로 공개하기

GitHub 계정과 저장소는 선택입니다. 계정을 만들고 빈 저장소를 생성한 뒤 소스만 올립니다. MIT LICENSE가 포함되어 있습니다.

공개할 파일: `src/`, `server/`, `scripts/`, `migrations/`, `public/`, `tests/`, 설정 템플릿, `package.json`, `package-lock.json`, README, SETUP, LICENSE.

공개하지 않을 파일: `.env.local`, `.dev.vars`, `.wrangler/`, 프로젝트 백업, 초대 코드, 관리 키 파일, 실제 여행 사진. `.gitignore`에 개발 파일 제외 규칙이 들어 있습니다. 공개 전에 직접 파일 목록을 확인하세요.

D1 ID·버킷명은 비밀번호가 아니지만, API 키는 공개 저장소에 올리지 말고 허용 사이트·API 제한을 적용합니다. Google·네이버의 장소 데이터나 타인의 사진에 MIT 라이선스가 적용되는 것은 아닙니다.

## 7. 자주 막히는 부분

| 증상                    | 먼저 확인할 것                                                     |
| ----------------------- | ------------------------------------------------------------------ |
| npm 명령이 없음         | Node.js 설치 후 터미널을 새로 열기                                 |
| 지도 대신 안내가 보임   | `.env.local` 위치·파일명·키 이름 확인, 서버 재시작                 |
| 지도에 오류가 뜸        | API 활성화, 결제 연결, 현재 주소 referrer 허용, 브라우저 콘솔 오류 |
| 장소 검색만 안 됨       | Places API (New) 활성화와 키 API 제한                              |
| 프로젝트 생성 실패      | 공유 서버 8787 실행, DB 마이그레이션, `/api/health`                |
| 사진 저장 실패          | R2 활성화·PHOTOS 바인딩·버킷명·2MB 제한·프로젝트 사진 수           |
| 준비 검사에서 D1 경고   | 로컬 개발은 계속 가능. 배포 전 실제 ID 입력                        |
| 5173/8787 포트 사용 중  | 먼저 켜둔 개발 서버를 종료하고 재실행                              |
| 코드가 맞는데 입장 불가 | 관리자의 코드 재발급·프로젝트 삭제 여부, 요청 제한 후 재시도       |
| 사진이 원본보다 작음    | 데이터 절약을 위해 1600px WebP로 변환하는 의도된 동작              |

## 개발 진행 순서

완료: 지도 중심 UI, 코드 참여, 장소·할 일, 오프라인 대기, 충돌 감지, 비공개 사진 공유, JSON·CSV 기본 가져오기, 로컬 통합 테스트.
이번 추가: 한 명령 로컬 실행, 설정 점검, 배포 전 검사, 저장소 상태 확인 API, 상세 준비 안내.
다음: 운영자의 키·계정 설정 후 실제 지도·검색 검증, 실제 두 휴대폰 공동 사용 확인, 가져오기 미리보기·사진 백업 개선.
구글·네이버 저장 목록 자동 수집과 자동 장소 매칭은 아직 포함하지 않습니다.
